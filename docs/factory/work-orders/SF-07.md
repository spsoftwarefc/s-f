## Goal and boundaries

Qualify SF-01–SF-06 as a **portable installation foundation** on synthetic new, existing, multi-component, custom/unknown, no-tests, conflicting and interrupted target repositories. This does NOT constitute release/deploy/CI-proof factory v1 (SF-08–SF-19 remain).

## Scope

- `tests/test_portability.py`: end-to-end isolated repository fixtures with exact before/after checks, synthetic command nonexecution, new/existing/monorepo/custom/no-tests coverage, repeated apply, version upgrade, conflict and safe remove, case/symlink and interrupted recovery.
- `tests/test_integrity.py`: negative acceptance and observed platform edge cases, as needed.
- `src/sf/` and existing tests: only demonstrated SF-07 blocker fixes with regression cases, no uncontrolled feature expansion.
- `.github/workflows/sf07-qualification.yml`: one pull_request-scoped, least-privilege, minimal native Linux and Windows Python-3.12 acceptance matrix; no push duplication, releases, secrets, PR writes or production hosts. Hosted jobs run only on PR #12 final stable candidate if workflow is installed.
- `docs/factory/SF07_QUALIFICATION.md` and `docs/factory/evidence/SF-07.md`: matrix, exact revision evidence, known limitations, acceptance disposition.
- `docs/factory/PROJECT.md` and `README.md`: synchronize state/merge cadence; no premature v1 claims.

## Acceptance

1. Rooted, offline synthetic targets: empty repo; Python service; Node UI with custom CI; Rust library; mixed Python/Node/Rust monorepo; custom build; no tests; nested instructions; dirty unrelated files; preexisting factory-owned and project-owned files.
2. Preserve exact project-owned bytes (instructions, CI, dependencies, user source), including CRLF/Unicode and local modifications. A preexisting AGENTS.md must not be silently changed; routing acknowledgment is explicit.
3. No package install, project command invocation, network, release, source-bot mutation, or hidden file writes during dry-run; effect scope matches immutable plan. Repeat apply/remove are no-op. Unexpected state fails closed.
4. Fault exercises journal creation, interruption in install/upgrade/remove and recovery; forged/stale plan, symlink, case collision and changes to owned content are rejected or reported unknown.
5. Native Linux and Windows Python 3.12, if hosted evidence is successfully obtainable, with exact GitHub run/job/attempt/commit identity. macOS remains unqualified until exercised. No hosted run is ever marked passed if not executed.
6. The baseline, test oracle and verification controls must be reviewed against changes to candidate code. G2 can be accepted only if all required platform fixture checks pass; G3+ and production release remain unqualified.
7. Only after G2 acceptance and GitHub merge requirements: integrate stack in dependency order while retaining work-order-before-implementation history. A failure blocks merge rather than lowering the gate.
