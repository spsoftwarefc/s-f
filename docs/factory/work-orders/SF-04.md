# SF-04 — Project profiles and explicit adapters

Status: declared, implementation not yet accepted.
Baseline: `129f39bf3cb108173ae7ed601d0fee9dc59eac4e` (PR #8 head).
PR: planned #9; stacked on `sf03/read-only-inventory`.
Purpose: enable project-owned component graphs and safe, declarative command adapters without invoking project commands or changing application dependencies.

## Scope
- `src/sf/profile.py`: compatible profile-v1 extension, strict bounds and validation, repository-path resolution.
- `src/sf/adapters.py`: deterministic component ordering and declarative Python/Node/Rust/Go/custom command suggestions.
- `src/sf/cli.py`: optional rooted profile validation, no execution.
- `tests/test_profile.py`, `tests/test_adapters.py`: positive, negative, path and graph fixtures.
- Documentation: example project profiles and contract notes.

## Invariants
- Read-only; no command execution, package installation, network, CI mutation or repository effects.
- Existing bootstrap profiles continue to validate; allow `cwd: "."` as an explicit safe repository-root path (update the old negative fixture with replacement traversal tests).
- Arbitrary custom projects can supply explicit argv, independent of language detection.
- No unknown fields, malformed types, absolute/escaping paths, duplicate component IDs or dependency cycles.
- Filesystem validation, when requested, never follows an escaping symlink and never treats a missing working directory as valid.
- A declared check or adapter hint is not proof that a tool exists or that a release is qualified.

## Acceptance
- Valid Python/Node/Rust/custom and monorepo examples parse deterministically.
- Known and unknown dependency order deterministic; self-cycles, missing dependencies and multiple-node cycles fail.
- Invalid cwd, traversal, symlink escape and non-directory working paths rejected.
- Existing test suite remains passing, with explicit root-cwd compatibility correction.
- Exact-candidate local test results and reviewed diff documented; no GitHub Actions run unless provider-specific proof becomes necessary.

## Non-goals
No installer, command execution engine, credentials, deployments or automated merge.
Next: SF-05 installation planning. Merge boundary: PR #12, not this package.
