# SF-05 — Read-only installation planning

Status: DECLARED — implementation and acceptance pending.
Baseline: `704a3586eafab1a69c9fc5c77bff27e986ddd376` (PR #9 head).
Stack: planned PR #10 on `sf04/project-profiles-adapters`. Merge boundary remains PR #12.

## Objective
Add an offline, deterministic, zero-write `sf integrate --dry-run` that plans installing portable repository-local factory guidance into new and existing repositories without changing existing project controls. SF-06, not this package, owns apply/upgrade/removal.

## Declared scope
- `src/sf/integration.py`: bounded read-only target plan, additions/conflicts, preserved files, content fingerprints, ownership manifest, Git/CI proposal and trust limits.
- `src/sf/cli.py`: `sf integrate --dry-run --root <repo> --profile <path>` JSON entrypoint; never apply.
- `tests/test_integration.py`: new/existing/custom/nested/dirty/symlink/case-collision/oversized/path-safety and repeatability fixtures.
- `docs/factory/SF05_INSTALL_PLAN.md` and `docs/factory/evidence/SF-05.md`: plan schema, limitations, evidence.
- `docs/factory/work-orders/SF-05.md`: this prerequisite record.

## Plan contract
- Profile must pass SF-04 validation (including directories when rooted).
- Plan has version, source identity, root reference, read-only inventory fingerprint, deterministic proposed paths/content hashes, expected previous bytes/state, owned-file manifest, preservation/conflict report, CI integration proposal, and unresolved states.
- Exact existing desired content can be a no-op; changed content and project-owned instructions must never be silently replaced.
- A pre-existing AGENTS.md/CLAUDE.md, .github workflow, or project data is not overwritten; only factory-owned paths are eligible for future controlled apply.
- Symlink targets, non-directory parents, path containment failures and case-fold collisions are reported as blockers, with bounded work.
- No write, command execution, network call, package change, CI run, merge or external effect occurs in planning.
- Git metadata and dirty-worktree claims unsupported without trusted verification must be `unknown`, not clean.
- Recorded digests are planning preconditions. SF-06 must independently verify them under an authorized apply; this plan alone has no mutation authority.

## Acceptance
- Dry-run performed twice on unchanged fixtures produces byte-identical JSON and byte-identical target trees.
- New project gets planned factory-owned files and optional AGENTS routing only if absent.
- Existing and monorepo projects preserve native instructions, workflows, commands and data byte-for-byte, with manual integration clearly identified.
- Existing changed target, symlinked factory prefix, case collision and invalid path prevent unsafe mutations.
- No dynamic downloads, command execution or installed Actions workflow; no reviewer approval requirement.
- Local suite re-runs the SF-02–04 regressions; candidate evidence and diff review recorded before PR creation.
