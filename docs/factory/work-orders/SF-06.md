# SF-06 — Controlled apply, upgrade, removal and recovery

Status: declared, implementation pending.
Baseline: PR #10 head `30683cf31b10a32cf340cda3770a89f4633a48b8`.
Stack: planned PR #11 on `sf05/integration-planner`. No merge before PR #12 acceptance.

## Objective
Add deterministic, bounded filesystem mutation from SF-05 plans, preserving project instructions and unrelated files. A developer explicitly invokes apply/upgrade/remove/recover on a target checkout. These commands never run project scripts, download packages, rewrite CI, merge or deploy.

## Scope
- `src/sf/lifecycle.py`: strict plan revalidation and authorization boundary, trusted local replan for apply, ownership validation, non-destructive three-way upgrade decision, owned-path removal, journaled idempotent roll-forward recovery, safe cleanup and durable writes.
- `src/sf/cli.py`: explicit plan-file apply and conservative upgrade/remove/recover operations with root/profile selectors.
- `src/sf/integration.py`: limited, necessary planner compatibility corrections only, if demonstrated.
- `tests/test_lifecycle.py`: fixtures including interruption, conflicting/modified targets, malformed/forged/stale plans and journals, preservation, symlinks and repeat operations.
- `docs/factory/SF06_LIFECYCLE.md` and `docs/factory/evidence/SF-06.md`: authority, on-disk formats, proven behavior and restrictions.

## Authority and semantics
- A plan file alone **never grants authority**: apply requires a distinct explicit CLI invocation and equality with a freshly computed locally trusted plan from the supplied project profile/root, including its checksums and conflicts.
- Per-operation fresh preflight: all intended effects must pass before any mutation; changed target, symlink, casefold collision, path escape or missing ownership blocks.
- Journal must be created durably BEFORE effects and atomically publish enough exact before/after identities for recovery. Recovery defaults to checked roll-forward after verifying prior/current digests, with explicit conflict on unexpected state; no blind replay.
- Repeated apply/upgrade/remove are no-ops when their target state is already achieved.
- Upgrade verifies an existing owned manifest and its corresponding installed old profile, uses base/local/desired comparison and preserves unexpected local edits by reporting a conflict instead of automatic rewriting. Unrelated files are never touched.
- Removal deletes only exact documented owner-controlled bytes and safely removes empty factory directories. A modified owned file or foreign file stops removal before any changes.
- Durable journal is not a portable OS transaction and no protection against hostile concurrent filesystem writers or privileged administrators is claimed. Strong adversarial containment requires qualified platform isolation, planned for SF-07.
- No unilateral mutation of source bot, another repository, CI runners or deployment state. Test against isolated temporary project fixtures only.

## Acceptance
- Recomputed-plan exact match rejects crafted target paths/content, stale plan, malformed input and changed profile.
- Valid initial apply creates only approved owned paths, outputs explicit receipts, repeated apply has no writes.
- Interruption after journal creation and partial effects resumes safely, not reissuing completed effects; tampered intermediate target quarantined/blocked.
- Upgrade path demonstrates clean transition, idempotence, and preserved local edits/conflict. No silent replacement of existing AGENTS.md or CI.
- Remove accepts only matching owned content, preserves unrelated project data, recovers after mid-removal failure and is idempotent.
- Fault injection before/after mutation and durable journal; no false success on failed writes.
- Local Python suite including SF-02–05 regressions passes, exact GitHub blob equality established, and diff reviewed.
- Avoid hosted Actions minutes except if unique provider evidence is needed. Merge boundary remains PR #12.
